# API-023 클라우드 검증 — 2026-11-20

기준은 GitHub `1120cy-ml`의 `7d728f8d13640b0d7e4f5f2b9e90357870391aae`다. Python HTTP 서버를 추가했으며 기존 LightGBM 모델·학습 코드·시뮬레이션 규칙·XGBoost 비교 코드는 변경하지 않았다. 사용자 PC의 파일을 원격으로 수정한 기록이 아니다.

## 실행 환경과 검사

- Linux, Python 3.12.14, 별도 검증 가상환경. `requirements-api.txt`와 `requirements-xgboost.txt`를 설치했으며 `pip check`에서 의존성 충돌이 없었다.
- `python -m unittest discover -s tests -v`: 기존 73개와 새 18개를 합친 **91개 통과**, 실패 0·건너뜀 0, 6.522초. [원문 로그](api023-tests-2026-11-20.txt)
- 모델 무결성·CLI 점수 일치·모델 로드 1회·병렬 추론·400/401/422/503/500·민감정보 없는 오류/로그를 검사했다. 테스트 도중 기준 모델 8개 파일의 해시가 바뀌지 않았다.
- 별도 uvicorn 프로세스를 loopback의 임시 포트에 직접 기동했다. 실행 프로세스는 검증 종료 후 모두 종료했다. 배포나 상시 서버 생성은 아니다.

## 검증 범위의 한계

사용자 Windows Python 3.13에서 이번 HTTP 서버는 아직 실행하지 않았다. 기존 Windows ML 73개 테스트 성공과 혼동하지 않는다. [Windows 실행 안내](../api/API-023_HANDOFF.md)에 따라 별도로 확인한다.

Spring의 특징값 집계·HTTP 호출·RiskAssessment 저장·임계값 정책·재확인 연계, Spring→ML→업무 DB 통합 E2E는 이번 작업에 포함하지 않았다. DB·Flyway·Mock 파일을 변경하지 않았고 데이터 재생성·재학습·모델 승격·원격 배포·PR 병합도 수행하지 않았다.

합성 데이터 모델 점수는 실제 호텔의 보정된 장애 확률이나 객실 미제공 확정 사실이 아니다. 입력 산식의 담당 설계안과 팀 승인 범위를 기존 문서대로 유지했다.
