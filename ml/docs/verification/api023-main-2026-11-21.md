# API-023 — 병합 후 main 기준 적용 확인

2026-11-21 사용자가 최신 `main`에서 `1121cy-api023`을 만들고 로컬의 이전 작업 브랜치를 삭제한 뒤, API-023 추가 파일을 같은 기준에 적용해 확인했다. 검증 기준 커밋은 `85c391e702437f9b7c2c349f8427f36eba463568`이다. 이 기록은 클라우드 검증이며 사용자 PC의 HTTP 실행 완료 기록이 아니다.

## 적용 범위

기존 API 전달본 기준 `7d728f8`과 병합 후 main을 비교했다. `README.md`, `docs/api.md`, `ml/`에는 차이가 없었다. 새 main에 기존 API 추가 파일을 적용하고 실행 브랜치 안내를 `1121cy-api023`으로 갱신했다. API 소스·학습 소스·여섯 특성 규칙·LightGBM 기준 모델은 이전 전달본과 동일하다.

GitHub PR #3과 #4는 병합 완료 상태다. ML PR #4의 병합 결과 `bec8ca5`는 부모가 하나인 커밋이어서 원래 ML 브랜치의 커밋이 현재 HEAD의 조상으로 나타나지 않는다. 따라서 이전 브랜치를 삭제할 때의 Git 경고를 코드 미반영으로 해석하지 않는다. 사용자는 원래 기준 커밋 `b2c05a86f6af636f8d4f1796feb24670240d5d0f`을 `ml-v0.2-lightgbm-baseline` 태그로 GitHub에 보관했고, 클라우드에서도 태그 대상을 확인했다.

## 실제 검증

- Linux Python 3.12.14, 기존 API 및 XGBoost 의존성이 설치된 검증 가상환경.
- 전체 테스트 **91개 통과**, 실패 0·건너뜀 0, 5.554초. API/runtime 18개와 기존 회귀 73개를 포함한다. [단일 실행 로그](api023-main-tests-2026-11-21.txt)
- 이 main 기준 복사본에서 uvicorn을 기동해 실제 HTTP 점검 **8개 통과**. 준비 상태, 반복 추론·CLI 점수 일치, 인증 401, JSON 400, 버전·범위 422를 확인했다. [HTTP 출력](api023-main-live-2026-11-21.txt)
- 실제 예제 점수는 `0.38033996022231914`, 모델 버전은 `process-synthetic-lightgbm-0.2-84d386281d22`다.
- 검증용 서버는 종료했다. 기준 모델 파일 집합·해시, 기존 학습 핵심 소스와 API 소스의 불변을 확인했다.

11월 20일의 모델 누락 503·인증 미설정·병렬 HTTP 검증은 [기존 API 기록](api023-cloud-2026-11-20.md)에 별도로 보존한다. 코드가 바뀌지 않은 검사를 새로 수행했다고 중복 주장하지 않는다.

## 사용자 실행과 남은 연결

사용자는 기존 `CSRO` 폴더와 `1121cy-api023`을 그대로 사용한다. [실행 안내](../api/API-023_HANDOFF.md)에 따라 추가 파일을 적용하고 기존 `ml/.venv`에 `requirements-api.txt`를 설치한다. 이 클라우드 검사 이후 사용자 Windows에서도 수정 후 전체 91개와 실제 HTTP 점검 8개를 확인했다. [Windows 최종 기록](api023-windows-2026-11-21.md)에 후속 결과를 구분해 보존한다.

Spring의 특징값 집계·추론 호출·위험 평가 저장·재확인 연결과 업무 DB 통합 E2E는 별도 작업이다. 이번 적용으로 backend·frontend·llm·Mock·DB·Flyway·AGENTS 파일은 변경하지 않았다.
