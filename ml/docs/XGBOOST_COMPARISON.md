# XGBoost 후속 비교 — 실행 계획

기준본은 `b2c05a8`의 LightGBM·규칙 모델이며 이번 비교는 독립적인 오프라인 후속 실험이다. LightGBM 기준 모델, 데이터 생성 규칙, 여섯 특성, 관측 라벨, 기간 분할, DB·API 계약을 유지한다. XGBoost 점수에 맞춰 데이터를 다시 생성하거나 과거 장애율의 중요도 순위를 강제하지 않는다.

실행 전 고정한 설정은 `config/xgboost_comparison_v0.2.json`이다. CPU 전용 XGBoost 3.4.1, seed 42, 단일 스레드, 깊이 3/4/5 × min_child_weight 1/5의 여섯 후보를 비교한다. 학습률 0.03, 최대 2,000회, 10월 검증 AP로 50회 조기 종료한다. LightGBM도 여섯 후보였으므로 탐색 횟수를 맞추되 서로 다른 라이브러리의 파라미터가 같은 의미라고 가정하지 않는다.

후보와 분류 임계값은 10월 검증 데이터로만 정한다. 선택한 체크포인트와 설정을 파일로 고정한 후 11~12월 평가를 수행한다. 기존 LightGBM·규칙의 임계값은 원래 메타데이터의 값을 유지한다. 전체 적격 대기열의 UNKNOWN도 포함해 일일 상위 10개 선정과 라벨 관측률을 보고한다.

기존 LightGBM의 11~12월 성능을 이미 확인한 뒤 추가한 비교이므로 이번 결과는 후속 탐색 비교다. 새로운 독립 최종 검증으로 해석하지 않는다. 같은 합성 세계의 비교이며 실제 호텔 예측 성능, 새로운 호텔 일반화, 실제 운영의 개선 효과를 입증하지 않는다. 이 실험으로 서비스 모델을 자동 교체하지 않는다.

`generated_reference_csv`는 완전한 생성 출력이 아닌 인계용 CSV 사본이다. 기존 `travel_ml train`에 그대로 넣는 방식은 지원하지 않는다. 이번 별도 비교 명령은 원래 LightGBM 메타데이터의 CSV·설정·전체 생성 manifest 해시에 묶인 사본만 받아 고정된 모델 비교에 사용한다.

Windows 적용·실행은 [XGBOOST_WINDOWS.md](XGBOOST_WINDOWS.md)를 따른다.


## 최초 클라우드 실행 — 2026-11-20

- Python 3.12.14, XGBoost CPU 3.4.1, LightGBM 4.7.0. 기존 NumPy·scikit-learn 등 고정 버전 유지.
- 전체 자동 테스트 **71개 통과(5.409초, 건너뜀 없음)**. 기존 62개와 새 비교 무결성·누수 방지 테스트 9개를 포함한다. XGBoost를 설치하지 않은 기본 환경에서는 선택 의존성에 해당하는 새 테스트 9개를 명시적으로 건너뛴다.
- 이 최초 실행 시점에는 새 XGBoost의 Windows 실행을 아직 확인하지 않았다. 이후 아래 수치 호환성 보완과 Windows 성공 기록이 이어진다.
- 학습 15,246행, 검증 2,341행. 테스트 달력 패널 6,100행 중 적격 6,005행, 확인 라벨 5,204행(장애 84행), UNKNOWN 801행, 빈 대상 95행. 적격 대상의 라벨 관측률 86.66%.
- 선택된 XGBoost: 깊이 5, min_child_weight 5, 35회(0부터 세는 best_iteration 34). 검증 F1 임계값 0.26301437616348267.
- 기존 LightGBM의 테스트 지표가 원래 결과와 완전히 일치했다. 생성/학습 원본과 여섯 특성·정답은 변경하지 않았다.

아래 테스트 지표는 확인 라벨 5,204행에서 계산했다. AP는 sklearn average precision이며 단순 정확도나 사다리꼴 PR 적분과 구분한다.

검증 AP 기준의 비교 권고는 테스트를 보기 전에 XGBoost로 고정됐다. 테스트 구간에서는 LightGBM의 AP·재현율·F1이 더 높고, XGBoost의 정밀도가 더 높았다. 검증 권고는 그대로 기록하며 이 결과만으로 모델을 자동 교체하지 않는다. 차이의 통계적 확실성이나 현실 성능 우월성을 검증한 실험은 아니다.

일일 상위 10개 검토는 각 모델 610개를 선택했다. LightGBM은 확인된 장애 61개·UNKNOWN 154개, XGBoost는 확인된 장애 60개·UNKNOWN 160개를 포함했다. UNKNOWN이 차지한 자리를 유지했고, 알려진 정답의 재현율은 각각 72.62%·71.43%다. 이 수치를 위 분류 임계값의 재현율과 혼용하지 않는다.

XGBoost 검증 순열 중요도(5회)의 평균 AP 감소량은 과거 장애율 0.316925, 대상 예약 수 0.305985로 측정됐다. 이 실험에서는 과거 장애율이 1위였으나 두 특성의 상관과 반복별 변동이 있으며 중요도 순위를 일반화하지 않는다. 기존 LightGBM의 중요도 결과는 그대로 보존한다.

## 수치 경계 호환성 보완 — 2026-11-20

사용자 Windows에서 새 71개 테스트는 15.274초에 통과했으나 실제 비교의 사전 검사에서 `Reference exposureRule validation threshold metrics did not reproduce`로 중단됐다는 출력을 받았다. 이 단계는 XGBoost 학습과 결과 저장 전이다.

검증 행 HOTEL-098 / 2025-10-05의 과거율 `0.040229885057471264`, 예약 수 7에 대한 점수가 동결 임계값 `0.2498112275967828`의 경계에 있다. `log1p/expm1`의 플랫폼별 마지막 비트 차이가 판정을 바꿀 수 있다. 사용자가 이어 제공한 실제 Windows 값은 `0.24981122759678273`, 동결 임계값과의 차이는 `-5.551115123125783e-17`로 확인됐다. 즉 임계값보다 2 ULP 작아 경계의 양성 1건이 제외되는 원인을 확인했다. 이 경계를 재현해 구현을 보완했다.

보완은 수식 `1-(1-p)^n`을 `Fraction.from_float(p)`와 정수 n으로 정확히 계산하고 마지막에 한 번만 float로 바꾸는 것이다. 기존 core·데이터·LightGBM/XGBoost 설정·저장된 임계값과 검증 허용오차는 바꾸지 않았다. ULP 구간을 임의로 양성에 포함하거나 F1 허용오차를 늘리는 방법은 사용하지 않았다.

- 실제 경계 입력의 정확 점수: `0.24981122759678281` → 동결 임계값 이상.
- 바로 앞 float의 과거율 `0.04022988505747126`은 정확 점수 `0.24981122759678276` → 임계값 미만을 유지한다.
- 새 회귀 2개를 포함해 **전체 73개 테스트 통과(6.827초, 생략 없음)**. 이 보완 시점에는 Windows 재실행을 기다렸으며 이후 아래 성공 기록으로 확인했다.
- 고정된 여섯 후보를 같은 데이터·설정으로 재실행한 결과 **XGBoost 모델 JSON은 이전과 바이트 동일**했고, 네 모델의 모든 검증/테스트/Top-K 지표도 동일했다. 데이터나 매개변수를 재튜닝하지 않았다.
- 선택 동결 기록은 비교 소스 해시만 새 값으로 정직하게 갱신했다. 그 필드를 제외한 모델 선택·라운드·임계값·데이터·프로토콜·권고 필드는 모두 동일하다.
