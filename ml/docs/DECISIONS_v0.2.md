# v0.2 설계 결정 기록

2026-11-18: 사용자가 “과거 장애율이 주요 특성이라는 점만 합의했고 나머지는 담당자가 정한다”고 확인했다. 따라서 아직 없는 여섯 필드의 팀 확정 계약을 기다리거나 v0.1 임시 예시를 그대로 복원하는 대신, 담당 설계 기준을 명시적으로 작성한다.

1. 여섯 특성: 과거 장애율 / 대상 확정 예약 수 / 최근 유입 증가 / 재확인 기한 초과 / 판매 재고 부족 신호 / 사전 성수일.
2. 가격 변동 대신 대상 예약 수: 호텔·날짜 “한 건 이상 실패” 라벨에서 노출량 차이를 직접 설명한다.
3. 과거 장애율은 예약별 확인 결과의 Beta(1,19) 수축 추정값: 적은 이력의 0%/100% 과잉 해석을 줄인다. 원비율과 관측 수는 감사 자료에 보존한다. 5%는 가상 사전값이다.
4. 라벨 집합은 D-1에 동결: 이후 신규 예약·늦게 받은 취소로 과거 예측 대상을 바꾸지 않는다.
5. UNKNOWN과 빈 대상을 0으로 채우지 않음: 확실한 실패 한 건이면 양성, 전부 확인된 정상이어야 음성이다.
6. 복구 후 정상은 정상, 대체 숙소 해결은 원호텔 장애를 지우지 않음: 최초 계약의 이행을 예측한다.
7. 준비 이력을 2024-09-01부터 생성: 4월 첫 90일 창과 예약 선행 기간 경계 문제를 피한다.
8. 실제 사건→관측→라벨: 위험 특성으로 정답을 직접 추첨하거나 완성 truth를 독립적으로 가리는 절차를 두지 않는다.
9. 같은 운영 복구 정책으로 모든 모델을 비교: 모델이 자기 평가의 라벨을 바꾸지 않는다.
10. 과거율의 중요도 1위를 강제하지 않음: 지속적 호텔 품질로 합리적 신호를 만들고 실제 중요도를 검증·보고한다.
11. 규칙 기준선에도 대상 예약 수를 반영: LightGBM과 비교할 때 OR 라벨의 노출량 효과를 공정하게 처리한다.
12. 모든 수치 매개변수는 가상 가정: 테스트 성능이나 원하는 발생률에 맞춘 조정은 하지 않는다. 파일럿 검수 후 테스트 공개 전에 설정을 고정한다.

다음 수정은 규칙 문서·JSON 설정·특성 스키마·테스트·평가 메타데이터를 함께 바꾼다. 기존 모델이나 CSV를 같은 버전 이름으로 재사용하지 않는다.
