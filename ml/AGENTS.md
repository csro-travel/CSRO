# ML 작업 문맥

ML 하위 파일을 구현하거나 변경하기 전에 `docs/ML_DATA_RULES_v0.2.md`, `docs/DECISIONS_v0.2.md`, `config/simulator_v0.2.json`, `schemas/features-v0.2.schema.json`을 읽는다.

- 주 seed 42, 100호텔, 2025년 대상. D-1 09:00 Asia/Seoul.
- 여섯 특성 중 과거 장애율이 핵심이라는 점만 팀 합의로 확인됐다. 나머지 산식/특성/매개변수는 담당 설계안이다. 팀 승인 완료로 바꿔 설명하지 않는다.
- 과정 기반 시뮬레이터의 관측 증빙에서 정답을 추출한다. 사후 truth masking이나 특성 수식으로 정답을 직접 뽑는 편법을 쓰지 않는다.
- 대상 집합 동결, UNKNOWN 제외, 시간 누수 방지, 라벨 성숙 경계, 고정 평가 구간을 유지한다.
- 현재 폴더는 시뮬레이터·특성/라벨 추출·학습·CLI 추론 구현을 포함한다. 실제 클라우드 실행 결과는 `docs/VERIFICATION.md`, `docs/RESULTS.md`에 기록한다. Windows 실행은 사용자 PC에서 별도로 확인한다. 규칙 원문의 초안 상태 설명은 당시 설계 기록이며 실제 완료 범위는 실행 기록을 따른다.
- 기존 `mock-server`, Spring 업무 DB·Flyway 파일을 이 ML 실험 때문에 자동 변경하지 않는다.
- 규칙 변경 시 문서·설정·스키마·버전·검증을 함께 갱신하고 이유를 기록한다. 과거 테스트 점수를 높이려는 사후 규칙 변경을 같은 실험으로 보고하지 않는다.
