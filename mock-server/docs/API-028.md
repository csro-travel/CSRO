# API-028 가상 공급사 대체 숙소 검색

[Notion v0.1 원문](https://app.notion.com/p/0002f2597c578319bf9701f007548476)과 첨부 요청·응답 스키마를 기준으로 한다. 원문은 설계 상태가 ‘진행 중’인 검토안이다. 구현했다는 이유로 팀의 설계 승인 상태를 바꾸지 않는다.

`POST /mock-supplier/v1/availability-searches`는 기존 Mock 서버의 서비스 Bearer 인증을 사용한다. 기본 주소는 `http://127.0.0.1:8001`이다. 기존 API-026/027의 호출 방법은 그대로다.

## 실행

기존 Mock 서버를 재시작한 뒤 새 PowerShell 터미널에서 호출한다.

```powershell
Set-Location C:\Users\cy102\Downloads\CSRO\mock-server
$mockHeaders = @{ Authorization = 'Bearer csro-local-mock-token' }
$searchBody = Get-Content examples\availability-search.json -Raw -Encoding UTF8
Invoke-RestMethod -Method Post `
  -Uri 'http://127.0.0.1:8001/mock-supplier/v1/availability-searches' `
  -Headers $mockHeaders -ContentType 'application/json' -Body $searchBody |
  ConvertTo-Json -Depth 10
```

2026-11-10 체크인~11-13 체크아웃, 성인 2명·객실 1개의 기준 요청은 A/B/C호텔의 3박 총액 480,000/510,000/465,000원을 반환한다. 각각의 거리는 800/1,400/2,600m이며 `source=SIMULATED_SUPPLIER`다. 금액은 필수 수수료를 포함한다.

## 데이터 의미와 경계

- 가상 조회 시각은 2026-11-09 10:15, 견적 만료 시각은 10:25(Asia/Seoul)이다. 오늘 날짜에 맞춰 숙박 기간을 자동 이동하지 않는다.
- 반경·정원·객실 수·동일 상품의 모든 숙박일 재고·선택적인 평균 1박 금액 한도를 적용한다. 조회는 재고를 차감하거나 객실을 확보하지 않는다.
- 조건에 맞는 후보가 없으면 `200`과 빈 `quotes`를 반환한다. 원래 기간을 바꿔서 후보를 만들지 않는다. 전체 기간이 비어 있을 때 장애가 확인된 날짜만 별도로 검색할 책임은 Spring에 있다.
- 명시적으로 요청한 1박 견적은 3박 견적과 다른 ID를 사용한다. 1박 총액을 원예약 3박 총액과 직접 비교하지 않는다.
- 1박·2실 등의 확장 fixture는 각 상품의 가상 일별 기본요금·필수 수수료를 숙박일 수·객실 수만큼 합산한다. 이 산식은 구현용 가상 데이터 규칙이며 실제 호텔의 날짜별 요금이나 팀의 가격 정책을 의미하지 않는다.
- `searchRequestId`는 추적용이다. 예약 멱등 키가 아니며, 검색 요청은 예약 실행 이력을 만들지 않는다.
- 업무 DB의 전역 견적 코드 UNIQUE 제약과 연결하기 위해, 검색 요청·조건과 상품·금액·재고·조회/만료 시각이 같은 스냅샷에는 같은 결정적 ID를 반환한다. 새 `searchRequestId` 또는 달라진 조건·스냅샷에는 SHA256 접미사가 붙은 새 ID를 반환한다. 같은 요청을 반복해도 재고를 확보하거나 차감하지 않는다.
- 원문 예제와 같은 `SEARCH-001`·`HOTEL-001`·3박·성인 2명·1실·반경 3000m·평균 1박 한도 300000원과 원래 상품·가격·고정 시각의 조합만 `QUOTE-A/B/C`를 그대로 유지한다. 다른 조건의 검색 결과 ID를 이 예제 ID로 간주하지 않는다. 이 검색별 스냅샷 ID 확장은 사용자 검토·승인에 따라 추가했으며 Notion 전체 설계 승인을 의미하지 않는다.
- 고정 fixture 범위 밖의 호텔·기간에는 후보가 없을 수 있다. 실제 전국 호텔 검색이나 운영 재고를 제공하지 않는다.
- 이 서버에는 업무 DB 접속이 없다. Spring 견적 저장·사건 화면 연결·고객 제안·선택·예약은 별도 작업이다.

요청 필드·타입 오류는 `400 INVALID_SEARCH_REQUEST`, 기간·인원의 의미 오류는 명세에 따라 `422`로 구분한다. 인증 실패는 `401 UNAUTHENTICATED_SERVICE`다. 오류는 기존 `application/problem+json` 형식을 사용한다.

## 검증

`mock-server`에서 `python -m unittest discover -s tests -p 'test_*.py'`를 실행한다. 고정 3박 견적, 빈 결과, 1박 요청, 검색 필터, 인증·잘못된 요청, 반복 검색의 비변경성을 확인한다. 실제 Windows 실행 여부와 Spring 연동 여부는 PR에서 별도로 표시한다.

원문 첨부 스키마 사본은 `schemas/api028_request.schema.json`, `schemas/api028_response.schema.json`에 있다. 원문이 개정되면 의미·호출자 영향을 확인한 뒤 함께 갱신한다.
