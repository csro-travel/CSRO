# API-029/030 — 별도 PostgreSQL의 가상 공급사 예약

[사용자 승인 최소 계약](../../backend/docs/api/API-015-016-PROPOSAL.md)과 [API-029](https://app.notion.com/p/a862f2597c5783e1b7af81b43a757fb0)·[API-030](https://app.notion.com/p/1312f2597c5783f89deb811742816432)·[Mock ERD-06](https://app.notion.com/p/99b2f2597c578398a54e816c1e8975d2)를 구현한다. 원본 API는 v0.1 검토안이며 팀 전체 설계 상태를 변경한 것은 아니다.

기본 `uvicorn app.main:app`는 기존 DB 없는 026/027/028을 유지한다. 029/030은 별도 상태 저장 모드가 준비되지 않으면 503이다. 실제 결제·환불·원예약 취소·입실·사건 종료를 수행하지 않는다.

## 실행 — Windows PowerShell

기존 8001 서버를 종료하고 프로젝트 루트에서 시작한다. 기존 업무 DB Compose·비밀번호·볼륨은 변경하지 않는다.

```powershell
Set-Location C:\Users\cy102\Downloads\CSRO
Copy-Item .env.mock.example .env.mock
code .env.mock
```

`.env.mock`의 예시 값을 충분히 긴 임의 비밀번호로 바꾼다. 이 파일은 Git에서 제외된다. 이미 만든 파일은 다시 복사해 덮어쓰지 않는다.

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $mockPasswordLine = @(Get-Content .env.mock | Where-Object { $_ -match '^MOCK_DB_PASSWORD=' })
    if ($mockPasswordLine.Count -ne 1) { throw 'Check the private .env.mock password line.' }
    $env:MOCK_DB_PASSWORD = ($mockPasswordLine[0] -split '=', 2)[1].Trim()
    if ([string]::IsNullOrWhiteSpace($env:MOCK_DB_PASSWORD) -or $env:MOCK_DB_PASSWORD -eq 'replace-with-a-long-random-local-password') {
        throw 'Set a private random password in .env.mock first.'
    }
    docker compose --env-file .env.mock -f compose.mock.yaml up -d --wait
    if ($LASTEXITCODE -ne 0) { throw 'Isolated Mock database startup failed.' }
    Set-Location mock-server
    .\.venv\Scripts\python.exe -m pip install -r requirements-stateful.txt
    if ($LASTEXITCODE -ne 0) { throw 'Optional Mock PostgreSQL installation failed.' }
    $env:MOCK_STATEFUL_ENABLED = 'true'
    $env:MOCK_SERVICE_TOKEN = 'csro-local-mock-token'
    $env:MOCK_BOOKING_AS_OF = '2026-11-09T10:20:00+09:00'
    .\.venv\Scripts\python.exe -m app.stateful_server
}
```

이 launcher는 HTTP를 127.0.0.1:8001에 고정하고 proxy header를 신뢰하지 않는다. 상태 저장 모드의 HTTP도 loopback 접근만 받는다. 기본 Mock으로 돌아가려면 해당 서버를 종료하고 현재 터미널에서 `Remove-Item Env:MOCK_STATEFUL_ENABLED` 후 기존 실행 명령을 사용한다.

DB 주소는 정확히 `127.0.0.1:25442/yeohaengbom_mock`, 사용자 `yb_mock`이다. 선택적으로 전달하는 MOCK_DB_HOST/PORT/NAME/USER가 다른 값이면 연결 전에 거부한다. 실제 접속 DB·사용자도 DDL과 모든 데이터 접근 전에 확인한다. 비밀번호는 환경변수로만 전달하며 DSN·토큰을 로그에 출력하지 않는다.

가상 판단 시각 `MOCK_BOOKING_AS_OF`는 필수이며 Spring `quote.search.demo-as-of`와 같아야 한다. HTTP body/header로 바꾸지 않는다. 028의 checkedAt은 이 시각, expiresAt은 10분 후다. DB의 처리 기록 created_at과 030 failedAt은 실제 감사 시각이며 confirmedAt은 가상 공급사 시각이다.

## 저장 및 재시작

`db/migration/V1__mock_supplier_schema.sql`은 ERD의 네 테이블과 원래 FK·CHECK·UNIQUE를 유지한다. 별도 예약 테이블을 만들지 않으며 Spring Flyway와 섞지 않는다. 정확한 전용 DB가 비어 있을 때만 DDL을 적용한다. 스키마 comment의 마이그레이션·실제 catalog 해시로 후속 시작의 구조 일치를 검사하고, 불일치 시 자동 수선 없이 중단한다.

가상 상품 A/B/C와 11/10·11/11·11/12 재고 9행 중 누락 행만 준비한다. 상품 메타데이터는 불변이며 좌표는 합성 예시다. 기존 800/1400/2600m fixture 거리와 지원 origin HOTEL-001을 유지한다. 재시작으로 재고·단가·견적·요청 결과를 덮어쓰거나 초기화하지 않는다. Compose 볼륨도 보존한다.

028은 모든 요청 숙박일의 최신 재고·단가를 일관된 스냅샷으로 읽고 견적을 불변 저장한다. 기간·객실 수에 따라 매 숙박일 단가를 합산한다. 정확한 초기 SEARCH-001 fixture만 QUOTE-A/B/C이며 조건·가격·재고·시각이 바뀌면 해시가 다른 ID다. 이전 stateless 견적은 새 Mock DB에 없으므로 전환 후 새 검색→제안→선택을 해야 한다.

## HTTP와 원자성

- `POST /mock-supplier/v1/replacement-bookings`: 서비스 Bearer, JSON, 필수 ASCII `Idempotency-Key` 1~100자. 본문은 quoteId/expectedTotalAmount/currency/guestReference만 받는다.
- 동일 요청 키 잠금→견적 행→숙박일 오름차순 재고 행 순서다. 모든 날짜 확보·기대 금액 일치 후 전일 재고 차감과 CONFIRMED/ALT/최초 201 결과를 같은 트랜잭션으로 커밋한다.
- 같은 키·본문은 저장된 HTTP 상태·본문을 만료·재고 재검사 전에 재생한다. 다른 본문은 409 IDEMPOTENCY_KEY_REUSED다.
- 알려진 견적의 가격 변경·만료·품절·상품 불일치는 재고를 바꾸지 않고 FAILED 및 최초 오류 응답을 커밋한다. 같은 quote의 다른 키 예약은 409 QUOTE_ALREADY_BOOKED로 보존한다. 실패 HTTP는 DB 커밋 뒤 생성한다.
- 없는 견적은 접수 전 404 QUOTE_NOT_FOUND이며 요청 행이 없다. 예상 총액이 달라져도 새 가격으로 자동 동의·예약하지 않는다.
- `GET /mock-supplier/v1/replacement-booking-requests/{requestId}`는 READ ONLY 트랜잭션으로 저장된 최종 결과만 읽는다. FAILED는 failureCode/failedAt과 null 성공 필드를 반환하며 PRICE_CHANGED만 currentTotalAmount/currency를 추가한다.
- 현재 Mock ERD는 CONFIRMED/FAILED만 저장한다. 진행 중 미커밋 요청은 030에서 404일 수 있다. 이것은 새 키 재예약을 허용하는 뜻이 아니다.

`MOCK_BOOKING_RESPONSE_DELAY_SECONDS`는 0~10초의 서버 전용 옵션이다. 예를 들어 6으로 설정하고 서버를 다시 시작하면 **새 성공의 커밋·DB 연결 반환 뒤** 응답만 6초 지연한다. Spring의 읽기 제한이 5초라면 결과 불명→같은 BRQ의 030 조회를 시연할 수 있다. 저장 결과 재생에는 지연을 적용하지 않는다. 가격·재고 변경은 격리 테스트/내부 도구에서만 수행하며 공개 관리자 API는 제공하지 않는다.

## 검증과 범위

기본 모드 검사:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

PostgreSQL 통합 클래스는 기본 실행에서 건너뛴다. 쓰기 검사에는 별도 `127.0.0.1:25443/yeohaengbom_mock_test`, 사용자 `yb_mock_test`, `MOCK_STATEFUL_TEST=true`와 MOCK_DB_PASSWORD를 명시한다. 운영/시연 DB 25442 및 업무 DB 5432를 테스트용으로 재사용하지 않는다. 테스트도 실제 DB 신원을 DDL 전에 확인한다.

Linux에서 DB 없는 검사 45개와 전용 PostgreSQL 검사 10개가 통과했다. 동시 동일 키, 다른 견적의 마지막 객실 경쟁, 중간 숙박일 품절의 전일 미차감, 가격 변경·만료 실패 재생, 같은 견적의 다른 키, 재시작 후 결과 보존, 읽기 무변경, 최신 숙박일 단가·불변 견적을 확인했다. Spring의 실제 응답 유실 복구와 두 브라우저 연결은 Linux에서 확인했다. Windows에서도 기본 45개·전용 DB 10개 검사가 통과했다. Windows 실제 브라우저 시연은 아직 확인하지 않았다. 합성 시연 내부의 정합성 검사이며 실제 공급사 성능·입실을 증명하지 않는다.
