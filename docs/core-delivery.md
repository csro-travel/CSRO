# 금요일 시연의 필수 흐름과 남은 결정

목표일은 **2026-11-27(금)**이다. 이 문서는 일정 제안과 코드에서 확인한 범위를 기록하며, 팀원의 담당·일정 확정을 대신하지 않는다.

기준은 [Notion E2E](https://app.notion.com/p/cfb2f2597c57821bb16e014bdc22c147)의 YB-001 전체 3박 고객 구제 흐름이다. 모든 예약·견적·입실 기록은 시연용 가상 데이터다.

## 완료 기준

위험 점검 → 공급사·호텔 근거 확인 → 사건 1건 → 같은 기간의 후보 3개 → 상담사가 고객에게 제안 → 고객이 실제 발송된 후보 선택 → 상담사가 가상 예약 실행 → 입실·필수 후속 업무 확인 → 사건 종료.

다음 보호 조건도 함께 통과해야 한다.

- 위험 점수만으로 장애를 확정하지 않는다. 나머지 미확인 숙박일은 그대로 구분한다.
- 선택만으로 예약을 확정하거나 예약 성공만으로 사건을 종료하지 않는다.
- 예약 응답 유실 시 같은 요청 ID로 결과를 조회한다. 중복 클릭으로 예약을 두 번 생성하지 않는다.
- 전 기간을 보장하지 못하거나 원예약 후속 업무가 미완료이면 종료를 차단한다.

## 실제 코드와 다음 순서

| 순서 | 기능 | 확인된 범위 / 다음 작업 |
| --- | --- | --- |
| 1 | ML·재확인·사건·채팅 | main에 구현됨. 운영 관측 수집·운영 인증과는 구분한다. |
| 2 | 결정적 더미 검색 API-028, 비교 API-025 | 이번 변경의 구현 범위. Spring 저장·화면까지 연결한 상태는 아니다. |
| 3 | Spring 검색 작업·견적 저장·사건 후보 표시 | API-009/010 최소 계약을 합의하고 기존 V1 테이블에 연결한다. |
| 4 | 고객 제안·선택 | API-013/014 최소 계약, 상담사·고객 인증 주체, 현재 제안·선택의 멱등 처리를 합의한다. |
| 5 | 가상 예약·결과 조회 | API-029/030 명세의 별도 Mock 저장소·원자 재고 처리부터 구현하고 Spring 예약 요청에 연결한다. |
| 6 | 입실·후속 업무·종료 | 필요한 숙박일 보장과 필수 업무 완료 조건을 검사하고 API-017/018·화면을 연결한다. |
| 7 | 통합 검증 | 대표 정상 흐름 1건, 가격/재고 변경과 응답 유실, 미해결 사건 종료 차단을 검증하고 시연을 고정한다. |

PR #17은 독립적인 검색 Agent와 후보 비교 화면을 추가했다. 현재 main에는 제안 전송·선택 저장·가상 예약·입실·종료 구현이 없다. 기존 화면을 활용하되, 실시간 Google/Airbnb 후보를 설계의 가상 공급사 확정 견적처럼 저장하지 않는다.

## 구현 전에 필요한 최소 결정

현재 읽을 수 있는 원문의 [API-009](https://app.notion.com/p/c022f2597c5783a18ac8818dfd4a4bed), [API-013](https://app.notion.com/p/6e12f2597c5783e9ac6b81fd03e48ab2) 등은 상세 JSON·오류·멱등성 계약 미작성 상태다. 다음 작업에서 구체적인 DTO와 오류 예시를 작성해 검토한 뒤 구현한다. 목록에 URI가 있다는 이유로 계약 확정으로 취급하지 않는다.

[API-029](https://app.notion.com/p/a862f2597c5783e1b7af81b43a757fb0)는 별도 Mock DB 안에서 전 숙박일 재고 차감·예약·요청 결과를 하나의 트랜잭션으로 저장하도록 요구한다. 현재 Compose에는 Spring 업무 DB만 있다. 업무 DB 재사용이나 고정 성공 응답으로 이 조건을 대체하지 않는다. Mock 저장소·공통 실행환경 추가는 [AGENTS.md](../AGENTS.md)의 사전 영향 설명·승인 대상이다.

고급 추천 가중치 실험, 새 ML 모델 학습, 실제 결제·환불·원예약 자동 취소, 실공급사 운영 연동은 이번 필수 흐름을 막지 않도록 후순위로 둔다.
