# 업무 규칙 변경 기준

## 유지할 규칙

- ML 위험 점수는 호텔과 체크인 날짜의 위험 신호다. 공급사 예약 상태, 숙박일별 객실 제공 여부, 위험 점수는 각각 별도로 관리한다.
- 호텔 원문, Agent의 해석, 검증된 사실을 구분한다. 예약번호·출처·숙박일을 확인한 근거만 해당 숙박일의 상태에 반영한다.
- 같은 예약의 추가 회신이나 신고는 기존 활성 사건에 연결한다. 활성 사건은 예약당 최대 한 건이다. 인증된 공급사 알림과 고객 현장 신고는 ML 평가를 기다리지 않고 접수한다.
- 기존 기간 전체를 보장하는 대체 견적을 먼저 찾는다. 가능한 견적이 없으면 장애가 확인된 숙박일을 대상으로 검색한다. 고객 선택, 상담사의 대체 예약 실행, 공급사의 예약 확정, 실제 입실은 각각 기록한다.
- 예약 결과가 불명이면 같은 요청번호로 상태를 조회한다. 입실 확인, 필요한 숙박일 보장, 원예약 후속 처리, 필수 업무 완료를 확인한 뒤 사건을 종료한다.

## 허용 범위와 승인

기존 업무 규칙을 구현하거나 상태의 의미와 전이 조건을 보존하는 내부 정리는 가능하다. 사건 생성·종료 조건, 근거 채택 기준, 고객 선택이나 예약 실행 권한을 바꾸려면 변경 이유·영향 범위·대안을 제시하고 승인받는다.
