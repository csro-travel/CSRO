## 의미와 구현 선택

- `stay.nights`는 `check_out_date - check_in_date`로 계산한다. 각 숙박일의 제공 가능 여부를 검증하는 기능은 아니다.
- `bookingStatus`는 공급사 계약 상태다. 활성 사건이 있거나 위험 점수가 높다는 이유로 변경하지 않는다.
- `support.needsAttention`은 현재 활성 사건 유무로 계산한다. 장애 확정값이나 ML 예측 확률이 아니다.
- Repository는 JdbcClient로 한 번에 조회한다. 이번 API에 JPA Entity CRUD를 별도로 추가하지 않았으며 같은 Spring DataSource를 사용한다.
- Service·Repository의 readOnly 선언만으로 시스템 전체 무변경을 증명하지 않는다. 실제 테스트 요청 전후 업무 행 비교를 별도로 수행한다.

## 이번 검토에서 보완한 내용

1. Java 클래스·엔드포인트 JavaDoc에 API-001 번호·명세 링크·역할·현재 범위를 표시했다.
2. JUnit DisplayName에 API-001과 검증 상황을 표시했다.
3. 후속 검증 코드가 ResponseStatusException400을 던질 때500으로 바뀌는 문제를 막도록 BAD_REQUEST를 INVALID_BOOKING_ID로 변환했다. 이 매핑만 검증하는 단위 테스트를 추가했다.

3번은 실제 ID 정규식 검증을 구현한 것이 아니다. 입력 형식 정책이 확정되면 validator와 실제 잘못된 경로 입력 테스트를 추가해야 한다.
