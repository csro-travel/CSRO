# 상담 대응 목록·고객 예약 화면 보강 — 사용자 승인 최소 변경

기준은 `main`의 `030a35b`다. Notion [최신 E2E UI 와이어프레임](https://app.notion.com/p/417e04d22bed81f5a001cd629e123dd0)의 screen_01(고객 예약), screen_02(목록), screen_03(상세)과 현재 화면을 대조했다. 사용자가 2026-11-26 대화에서 아래 4가지를 승인했다.

1. 고객 예약 정보 표시
2. 종료된 건 목록
3. 목록 검색과 상세 보강
4. 화면 명칭 "상담 대응 건"

기존 필드는 바꾸지 않고 모두 **추가**만 한다. Flyway와 테이블 변경은 없다.

## 화면 명칭

화면 문구의 "상담 사건"을 **"상담 대응 건"**으로 바꾼다(목록 제목 "상담 대응 목록").

- **바꾸지 않는 것:** API·DB·Notion·코드의 "사건/Case"(`caseId`, `cases`, API-003/004/018 등)
- **대응 관계:** 화면 "상담 대응 건" = 문서·API의 상담 사건(Case)
- **서버 문구:** 서버가 만드는 오류 문구와 SYSTEM 채팅 문구는 이번 범위에서 바꾸지 않는다

## API-003 사건 목록

| 항목 | 내용 |
| --- | --- |
| `status` | `CLOSED`를 추가로 허용한다. **명시적으로 요청할 때만** 종료 건을 반환하고, 기본 목록은 계속 OPEN/IN_PROGRESS/WAITING만 반환한다. 허용 외 값은 기존과 같은 400 `INVALID_FILTER`다 |
| `q` (신규, 선택) | 1~40자, 제어 문자 금지. 사건 번호·예약 번호·숙소명·고객 표시명에서 대소문자 구분 없는 부분 일치로 찾는다. 빈 값이나 범위를 벗어난 값은 400 `INVALID_FILTER`다 |
| 응답 항목 | `createdAt`(사건 생성 시각)을 추가한다 |

## API-004 사건 상세

`booking`에 `rooms`(객실 수)와 `originalPrice`(`{"amount","currency"}`, 원예약 총액)를 추가한다. 기존 `adults`도 화면에 표시한다.

## API-001 고객 예약 화면 연결

API-001 계약은 바꾸지 않는다. 고객 화면 `/customer/bookings/{bookingId}`가 API-001을 호출해 다음을 표시한다.
- 숙소, 기간, 박수, 인원, 예약 상태, 결제 금액
- 진행 중인 상담 링크(`support.activeCaseId`)

격리 시연 인증은 고객 토큰의 `GET /api/v1/bookings/{bookingId}`만 고객 주체로 연결한다. 고객 3101 프록시도 `GET /demo/bookings/{bookingId}`만 추가로 허용한다. 상담사 토큰으로 호출하면 기존 서비스 규칙대로 403이다.

## 검증

2026-11-26 Windows 실행 환경에서 다음을 확인했다.
- **HTTP:** 종료 필터(C-001), 한글 검색(숙소명·고객명), 사건 번호·예약 번호 검색, 허용 외 상태 400, 상세의 인원·객실·원예약 총액
- **브라우저:** 고객 예약 정보와 상담 링크, 목록 "종료" 탭, 한글 검색
- **자동 검사:** `ciUnitTest`(고객 예약 조회 인증 경계 포함), `demo-closure-proxy.cjs` 4개, 프런트 `tsc`

옛 문구로 화면을 찾던 브라우저 테스트 스크립트는 새 문구로 갱신했다.
