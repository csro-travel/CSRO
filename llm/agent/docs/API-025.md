# API-025 대체 숙소 견적 비교

[Notion 원본 계약 v0.1 검토안](https://app.notion.com/p/65a2f2597c5783eb9eda81113655eab4)을 기존 호텔 회신 Agent 프로세스에 구현한다. `POST /internal/v1/alternative-rankings`는 기존 `AGENT_SERVICE_TOKEN`의 Bearer 인증을 사용한다. 서비스·포트·업무 DB 소유권을 새로 나누지 않는다.

입력은 Spring이 검증·저장한 견적 스냅샷이다. Python은 견적 ID의 순서·설명·주의사항만 반환하며 가격·재고를 생성하거나 예약·고객 발송·업무 DB 갱신을 수행하지 않는다. `originalStayTotal`은 같은 기간 비교가 가능할 때만 넣으며, 생략할 수 있다. JSON `null`은 허용하지 않는다.

## 초기 비교 규칙

1. 날짜·인원·통화가 일치하는지 검사한다. 섞인 기간은 요청 전체를 422로 거부하며, 1박 검색은 별도 요청으로 비교한다.
2. 가장 가까운 후보를 먼저 둔다. 거리가 같으면 총액, 견적 ID 순으로 결정한다.
3. 나머지 후보는 총액, 거리, 견적 ID 순으로 둔다. 따라서 예시 A/B/C는 A/C/B가 된다.
4. `LOWEST_PRICE` 설명은 입력 전체의 최저 총액과 같은 견적에만 붙인다. 가장 가까운 후보가 이미 최저가이면 나머지 후보에 최저가라는 설명을 붙이지 않는다.

이는 검토 가능한 초기 구현 규칙이며 검증된 추천 가중치나 고객 효용 최적화를 뜻하지 않는다. LLM API·추가 모델 학습·외부 검색이 필요하지 않다. 응답 `rankingVersion`은 계약 예시의 `alternative-ranker-0.1`이다.

## 오류와 경계

| HTTP | code | 의미 |
| --- | --- | --- |
| 400 | `INVALID_RANKING_REQUEST` | JSON·필수 필드·엄격한 정수 타입·중복 ID·중첩 확장 필드 오류 |
| 401 | `UNAUTHENTICATED_SERVICE` | 기존 내부 Bearer 인증 실패 |
| 422 | `QUOTE_STAY_MISMATCH` | 체크아웃 순서 또는 견적의 기간·인원 불일치 |
| 422 | `CURRENCY_MISMATCH` | KRW 이외의 문자열 통화 입력, 환율 자동 변환 없음 |
| 503 | `AGENT_UNAVAILABLE` | 비교 처리기 이용 불가 |
| 500 | `INTERNAL_ERROR` | 예상치 못한 비교 오류 |

Notion 첨부 JSON Schema 원본은 [요청](../schemas/api025_request.schema.json)·[응답](../schemas/api025_response.schema.json)에 그대로 보존했다. 최상위 요청 확장은 허용하고 중첩 객체는 확장을 거부한다. 통화는 원본 스키마의 KRW 조건과 상세 명세의 `CURRENCY_MISMATCH`를 함께 적용해 문자열 통화의 의미 위반을 422로 분류한다.

`checkedAt`은 시간대를 포함하는 실제 입력값이며 현재 날짜로 덮어쓰지 않는다. 견적 만료·현재 재고·가격 재확인과 응답 ID 검증·저장은 호출자인 Spring 책임이다. 이 API 호출 성공은 실제 상담 사건·견적이 DB에 저장됐다는 증거가 아니다.

## 검증

기존 Agent 서버를 실행한 뒤 별도 PowerShell에서 예제를 호출할 수 있다. 아래 토큰은 실행 중인 Agent에 설정한 `AGENT_SERVICE_TOKEN`과 같아야 한다.

```powershell
Set-Location C:\Users\cy102\Downloads\CSRO\llm\agent
$agentHeaders = @{ Authorization = "Bearer $env:AGENT_SERVICE_TOKEN" }
$rankingBody = Get-Content examples\alternative-ranking.json -Raw -Encoding UTF8
Invoke-RestMethod -Method Post `
  -Uri 'http://127.0.0.1:8000/internal/v1/alternative-rankings' `
  -Headers $agentHeaders -ContentType 'application/json' -Body $rankingBody |
  ConvertTo-Json -Depth 8
```

이 예제는 동일한 3박의 A/B/C 고정 입력을 사용한다. 실행 중인 Spring DB의 저장 견적을 자동 조회하지 않는다.

`llm/agent`에서 실행한다. 기존 API-024와 공유하는 인증·오류 처리의 회귀도 함께 확인한다. 테스트는 외부 API나 업무 DB를 사용하지 않고 임시 로컬 HTTP 포트를 연다.
